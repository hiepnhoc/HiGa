Mở đầu: AWS giờ gom agentic AI thành hai nhánh — một cho người làm nghiệp vụ (Quick), một cho dev (Kiro). Hôm nay đi qua từng cái, nhấn use case, cuối cùng có bảng so sánh và phần demo.

Cùng một hướng, hai đối tượng

Amazon Quick

Business user, knowledge worker

  • Hỏi dữ liệu doanh nghiệp → insight → hành động trên app
  • Kế thừa Amazon Q Business + QuickSight
  • Research, BI, automation trong một workspace

Kiro

Developer, engineering team

  • Prompt → spec → code đã verify
  • Kế thừa Amazon Q Developer (ngừng 15/5/2026)
  • Một agent harness: IDE, CLI, Web, Mobile, Crew
Điểm chốt để người nghe không lẫn: Quick là "Copilot phiên bản AWS" cho business; Kiro là coding agent. Cả hai đều là agent, đều có MCP, đều chạy trên nền Bedrock/Claude.

Amazon Quick

Một workspace, sáu khối

Quick Chat & Spaces

Giao diện hội thoại; Spaces gom tài liệu, dữ liệu, ngữ cảnh theo team hoặc cá nhân.

Quick Index

Lớp nền chạy ngầm, index mọi nguồn: database, warehouse, document, email, file upload.

Quick Research

Deep research kết hợp dữ liệu nội bộ, dữ liệu bên thứ ba và web; báo cáo có trích dẫn.

Quick Sight

QuickSight cũ: dashboard, forecast, hỏi dữ liệu bằng ngôn ngữ tự nhiên.

Quick Flows

Tự động hoá việc lặp lại bằng cách mô tả workflow bằng lời, không cần kỹ thuật.

Quick Automate

Orchestration nhiều bước, nhiều agent: monitoring, versioning, human-in-the-loop duyệt trước khi chạy tiếp.

Cộng thêm: Apps in Quick (xây app bằng ngôn ngữ tự nhiên), desktop app, browser extension (gõ @Quick trên thanh địa chỉ, bôi đen text để tóm tắt).

Nếu người nghe là dân QuickSight: nói rõ dashboard cũ không mất, chỉ đổi tên thành "Quick Sight" và nằm trong workspace lớn hơn. Flows cho người dùng thường; Automate cho team kỹ thuật, cần tier Enterprise.

Amazon Quick

Use case kinh điển

Đối soát hoá đơn hàng loạt

Team Finance của Amazon dùng Quick Automate để đối soát hàng nghìn hoá đơn mỗi tháng — đọc file, khớp với hệ thống, đẩy ngoại lệ cho người duyệt.

Tổng hợp xuyên hệ thống

Demo của AWS: kéo insight và đề xuất workflow từ 5–6 hệ thống doanh nghiệp trong ~5 phút, thay vì 30–45 phút làm tay.

Báo cáo research định kỳ

Quick Research chạy như một bước trong Quick Flows: lên lịch tự sinh báo cáo thị trường / đối thủ có trích dẫn, chia sẻ cho cả phòng.

Ops văn phòng hằng ngày

Tóm tắt email, trả lời tin nhắn, cập nhật ticket, soạn content — dùng dữ liệu nội bộ, ngay trong tab trình duyệt đang mở.

Gợi ý cho công ty chứng khoán: Research báo cáo ngành từ tài liệu nội bộ + web; Flows tự động tổng hợp ticket CS hằng ngày; Automate luồng duyệt đa cấp.

Ba use case đầu là ví dụ chính thức của AWS; dòng cuối là gợi ý của mình cho bối cảnh ACBS, nói rõ đó là ý tưởng chứ chưa làm.
Kiro

Một agent harness, nhiều bề mặt

  • Cloud session: bắt đầu trên web, giao task dài, gập laptop; check lại từ điện thoại, terminal hay IDE — cùng steering, cùng tool.
  • Model: Claude Opus 4.8, hoặc Auto trộn nhiều frontier model để cân chất lượng / độ trễ / chi phí.
  • Powers: gắn context + tool theo domain khi cần, không nhồi vào mọi request.
  • Login GitHub / Google / Builder ID / IAM Identity Center. Không cần AWS account.
Ý chính: Kiro không còn là "một IDE" mà là một agent chạy sau nhiều giao diện, giao tiếp qua ACP. Crew chỉ là bề mặt mới nhất, dùng lại nguyên harness và cấu hình .kiro.

Spec-driven development

Prompt

Một câu yêu cầu

"Thêm luồng mở tài khoản…"

requirements.md

User story + EARS

Acceptance criteria viết theo EARS, bạn duyệt trước khi đi tiếp.

design.md

Kiến trúc

Lộ trade-off, ràng buộc, data model, sequence.

tasks.md

Task tuần tự

Mỗi task link về requirement & design; agent chạy song song.

Verify

Property-based test

Dùng công cụ deterministic để chứng minh code đúng ý.

Ba mức tuỳ việc

Agent session cho fix nhanh · Quick spec để làm rõ ý · Full spec flow cho feature lớn.

Spec sống cùng code

Spec cập nhật khi code đổi — đồng thời là tài liệu cho team.

Thay vì vibe coding

Giải bài toán codebase lớn, context dễ hiểu sai, quyết định không ai ghi lại.

Đây là slide demo chính nếu demo IDE: mở một repo, gõ prompt, cho mọi người xem Kiro sinh requirements.md trước, dừng lại duyệt, rồi design, rồi tasks. Nhấn chỗ "bạn duyệt trước khi đi tiếp".
Kiro IDE

Hooks, Steering, Autopilot

Agent Hooks

Agent chạy theo sự kiện: save file → cập nhật test; đổi API → refresh README; trước commit → scan security. Cấu hình trong .kiro/hooks/.

Steering

Markdown trong .kiro/steering/: product, structure, tech. Kiến thức bền vững về convention của team, không phải giải thích lại mỗi chat.

Autopilot

Giao task lớn chạy tự động; vẫn hỏi bạn khi chạy script / command. Tắt để duyệt từng diff.

Agent Focus Mode

Command center quản lý nhiều agent trên nhiều repo, sandbox local hoặc cloud; quay lại IDE đầy đủ khi cần sửa tay, debug. (experimental)

Multimodal & MCP

Thả ảnh UI design / ảnh whiteboard kiến trúc để Kiro bám theo. Kết nối tool qua MCP, Powers gắn chuyên môn theo domain.

Nền VS Code

Base trên Code OSS: import settings, theme, plugin Open VSX. Diagnostics lỗi, sinh commit message, hiển thị credit từng prompt.

Nếu còn thời gian: show file steering của dự án, rồi một hook đơn giản (save file test → chạy test). Nói thẳng Agent Focus Mode còn experimental.
Kiro IDE

Use case kinh điển

Feature phức tạp trên codebase lớn

Spec → design → tasks → nhiều agent build song song → verify. Ít vòng lặp hơn vibe coding, có tài liệu để review.

Refactor cần plan trước

Spec dùng để mô tả hành vi hiện tại của hệ thống cũ trước khi đụng vào — hữu ích với service legacy không ai nhớ.

Giữ chuẩn team bằng hook

Test, doc, security scan tự chạy khi save / commit — "senior dev không bao giờ quên" cho người mới.

Chuẩn hoá output AI

Steering ép naming, library, pattern của team → output đúng convention, giảm comment trong code review.

Ví dụ gần: một service Quarkus mới cần bộ API đầy đủ — viết spec từ Figma + tài liệu nghiệp vụ, để Kiro sinh requirements, mình duyệt rồi mới cho build.

Dòng cuối là ví dụ sát việc của phòng: luồng mở tài khoản trái phiếu có Figma và danh sách API sẵn — đúng kiểu đầu vào spec-driven thích.

Kịch bản mở đầu của AWS

Chiều thứ Sáu, đồng nghiệp ping một latency spike. Bạn nhớ từng xử lý case tương tự: metric nào, test nào, log ở đâu — chỉ là phải mở 5 tool cùng lúc.

Với Crew: nhắn một câu, Crew tìm lại lần trước đã làm gì, viết lên, gửi cho đồng nghiệp. Bạn tắt máy; tối thấy note "đã resolve".

Ra mắt 4/8/2026 · open source Apache 2.0 · chạy trên Kiro CLI, đọc lại .kiro sẵn có.

Nhấn mạnh Crew không phải IDE mới: nó là lớp orchestration ở trên, dùng lại harness. Bạn là "integration layer" giữa các tool của mình — Crew nhận phần đó.
Kiro Crew

Bốn thứ làm nên "chạy khi bạn vắng"

Tự học, tự tiến hoá

Memory mang preference, context project, lịch sử vào session mới. Sửa sai → lesson bền vững (có scope theo workspace). Việc lặp lại → skill có thể xem, sửa, xoá. Tất cả hiển thị — bạn quyết Crew mang theo gì.

Lịch, heartbeat, webhook

Job định kỳ (morning digest). Heartbeat theo dõi PR / deployment tới khi đổi trạng thái. Webhook có xác thực kích hoạt từ sự kiện ngoài. Job không cần reasoning chạy script thuần, không tốn model. Task dài đi qua checkpoint, validate, retry.

Nhiều agent, điều phối qua ACP

Nhiều conversation chạy đồng thời, context tách biệt; hoặc giao research / implementation cho subagent rồi trả về conversation cha. Activity view: thấy reasoning, từng tool call, mỗi agent một card.

Apps & kênh

Giao diện chuyên biệt kết hợp UI + agent + skill + lịch: DevFleets (worktree), Task Runner, Issue Radar (triage issue/PR), LaunchDarkly. Tự xây bằng App SDK. Làm việc từ Mac app, web, TUI, Slack, Discord, Telegram, Teams, WeCom.

Nếu demo Crew: cho xem dashboard với Activity view và một schedule đơn giản (morning digest check PR). Thấy được reasoning + tool call theo thời gian thực là điểm ăn tiền với người lo về "AI tự chạy".
Kiro Crew

Bảo mật & mô hình mở

Defense in depth từ commit đầu

  • OS-level sandbox; command deny-by-default
  • Chặn pattern đáng ngờ, chặn sensitive path, validate input
  • Redact credential; audit log có ký cho mọi action
  • Tool request có thể bắt buộc duyệt; dashboard bind local mặc định
  • Chạy trên hạ tầng bạn kiểm soát: laptop, container, VM — không cần AWS account, không control plane của AWS

Open source — nhưng đọc kỹ chữ nhỏ

  • Bắt đầu là side project MeshClaw trong Amazon; <6 tháng có 39.000 builder, ~500 contributor
  • Lớp orchestration: Apache 2.0, governance công khai (MAINTAINERS.md, proposal bằng PR)
  • Agent harness bên dưới vẫn proprietary; Crew chạy trên Kiro CLI và cần Kiro account (có free tier)
  • Hỗ trợ ACP + MCP, skill từ nền tảng khác chạy không cần sửa; coding agent khác cần connector riêng
Với bối cảnh công ty chứng khoán: điểm "chạy local, audit log có ký, deny-by-default" là thứ đem đi nói chuyện với bảo mật. Nhưng cũng nói thật: harness đóng, token đi qua Kiro.
