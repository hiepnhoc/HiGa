Amazon Quick

Quick Chat & Spaces

  • Chat: hỏi, giao việc cho agent. Một chat thường đính kèm tối đa 20 file.
  • Space: kho tri thức của một team / mảng nghiệp vụ. Không chỉ là thư mục file — gom 4 loại knowledge.
  • Chọn Space làm ngữ cảnh → agent chỉ trả lời trong Space và chỉ dùng Actions gắn vào Space đó.
  • Tới 10.000 file, tổng 10 GB; PDF/Word/PPT ≤ 500 MB/file.
  • Share Space không tự cấp quyền dashboard bên trong — quyền tài nguyên giữ riêng.

Chat là chỗ hỏi; Space là kho tri thức có phân quyền, là ngữ cảnh để agent trả lời đúng mảng.

Câu hay bị hỏi: "Space có phải folder không?" — Không hẳn: ngoài file còn có knowledge base nối nguồn sống (SharePoint…), dashboard, và Actions. Và Space chính là thứ giới hạn phạm vi trả lời + phạm vi hành động của agent.
Amazon Quick

Quick Index

  • Lớp index chạy ngầm, tự động — nhưng chỉ index những gì bạn đưa vào (upload hoặc connector), không tự quét cả công ty.
  • Thấy nó qua trạng thái file: Uploading → Processing → Text ready → Ready.
  • Giữ quyền gốc của nguồn: không có quyền trên SharePoint thì hỏi trong Quick cũng không ra.
  • Không chọn embedding / chunking / vector DB — đổi lại không phải vận hành.
  • Dung lượng theo GB file gốc: Pro 25 GB/user, Enterprise 50 GB/user; vượt $5/GB/tháng, auto-purchase mặc định.

Quick Index là kho index tự động; mình chỉ "cho ăn" qua Space và connector.

Nếu bị hỏi "có thay được Bedrock Knowledge Bases không": Quick Index là cho người dùng cuối trong Quick; Bedrock KB là cho dev build app riêng — khác mục đích. Admin quản dung lượng ở Manage Quick → Subscriptions → Index capacity.
Amazon Quick

Quick Research

  • Agent deep research: đưa một đề tài, nó lên plan, đi nhiều nguồn, trả về báo cáo có trích dẫn.
  • Bạn sửa plan trước khi chạy và góp ý giữa chừng.
  • Nguồn: nội bộ (Space, KB, dashboard), web + tin tức 200+ đầu báo, dữ liệu bên thứ ba: FactSet, S&P Global, IDC (cần subscription sẵn), US Patents, PubMed.
  • Chạy được như một bước trong Flows → báo cáo định kỳ.
  • Tính bằng agent hours: Pro ~2 giờ/tháng, thêm ~$6/giờ.

Chat hỏi gì đáp nấy; Research là giao đề tài, nhận về tài liệu dùng lại được.

Gợi ý ACBS: nếu công ty đã có FactSet hoặc S&P Global, Research trộn được báo cáo nội bộ của phòng phân tích với dữ liệu đó và tin tức, ra bản tổng hợp ngành có trích dẫn. Cần hỏi bộ phận mua data trước.
Amazon Quick

Quick Sight

  • Chính là QuickSight cũ — dashboard, dataset, phân quyền giữ nguyên khi chuyển sang Quick.
  • Nối dữ liệu bảng: Redshift, Athena, S3, RDS, Snowflake, Databricks…
  • Topic gắn nghĩa nghiệp vụ cho cột → hỏi số liệu bằng lời, trả về biểu đồ.
  • Forecast, phát hiện bất thường; dashboard gắn được vào Space để Chat/Research dùng.
  • Tạo / sửa dashboard cần tier Enterprise; Professional xem và hỏi.

BI cũ không mất, chỉ được nối thêm vào chat và agent.

Câu ví dụ trên hình là minh hoạ. Điểm nói: người không biết SQL vẫn hỏi được số liệu nếu team data dựng Topic tốt — Topic là chỗ đầu tư.
Amazon Quick

Quick Flows & Quick Automate

  • Flows: ai cũng tạo được, mô tả bằng lời. Bước có thể là chat, Research, Action. Chạy tay hoặc theo lịch, share cho cả phòng. Có cả ở tier Free.
  • Automate: cho team kỹ thuật, quy trình nhiều bước, nhiều hệ thống, nhiều agent. Có rẽ nhánh, human-in-the-loop duyệt trước khi chạy tiếp.
  • Automate có monitoring, debug, versioning, phân quyền, deploy — cần tier Enterprise.

Flows thay Zapier cho việc cá nhân; Automate cho quy trình xuyên phòng ban cần kiểm soát.

Làn dưới là use case kinh điển của AWS: team Finance của Amazon đối soát hàng nghìn hoá đơn mỗi tháng. Flow làn trên là ví dụ minh hoạ, làm được ngay ở tier Free.

Kiro

Một agent harness, nhiều bề mặt

  • Kiro không còn là "một IDE": một agent harness nói chuyện qua ACP, các giao diện chỉ là cửa vào.
  • Cloud session: giao task trên web, gập laptop, check lại từ điện thoại, terminal hay IDE.
  • Cùng steering, skills, MCP ở mọi bề mặt — cấu hình .kiro đi theo.
  • Model: Claude Opus 4.8 hoặc Auto. Powers: gói context + tool theo domain, gắn khi cần.
  • Login GitHub / Google / Builder ID / IAM Identity Center; không cần AWS account; có free tier.
Crew chỉ là bề mặt mới nhất, dùng lại nguyên harness và cấu hình .kiro — đó là lý do demo IDE trước rồi sang Crew vẫn liền mạch.

Spec-driven development

Prompt

Một câu yêu cầu

"Thêm endpoint tính phí cho một lệnh…"

requirements.md

User story + EARS

WHEN … THEN hệ thống SHALL … — bạn duyệt trước khi đi tiếp.

design.md

Kiến trúc

Trade-off, ràng buộc, data model, sequence.

tasks.md

Task tuần tự

Mỗi task link về requirement & design; agent chạy song song.

Verify

Property-based test

Công cụ deterministic chứng minh code đúng ý.

Ba mức tuỳ việc

Agent session cho fix nhanh · Quick spec để làm rõ ý · Full spec flow cho feature lớn.

Spec sống cùng code

Đổi yêu cầu → sửa spec trước, code sau. Spec là tài liệu cho team đọc.

Thay vì vibe coding

Codebase lớn, context dễ hiểu sai, quyết định không ai ghi lại — spec giữ lại hết.

Kiro IDE

Agent Hooks

  • Agent chạy theo sự kiện, không cần ai gõ prompt.
  • Sự kiện: lưu file (PostFileSave), trước/sau tool call, kết thúc session.
  • Matcher regex lọc file hoặc tool. Action: agent (chèn prompt) hoặc command (chạy shell).
  • File JSON trong .kiro/hooks/, commit cùng repo → cả team dùng chung.
  • Tạo bằng lời: "Ask Kiro to create a hook".

Như một senior dev không bao giờ quên cập nhật test và tài liệu.

Demo: đổi path trong FeeResource.java, lưu → hook chạy → mở docs/API.md đã cập nhật. File JSON trên hình nằm trong demo kit.
Kiro IDE

Steering

  • Markdown trong .kiro/steering/ cho Kiro kiến thức bền vững về project: không phải giải thích lại mỗi chat.
  • Ba file nền: product (mục đích), tech (stack, ràng buộc), structure (layout, naming). Bấm "Generate Steering Docs" là có.
  • Chế độ nạp: always, fileMatch theo pattern, manual gọi bằng #tên, auto theo mô tả.
  • Global ở ~/.kiro/steering; workspace thắng khi xung đột. Hỗ trợ cả AGENTS.md.

Viết convention một lần, mọi agent — IDE, CLI, Crew — đều theo.

Demo kit có sẵn product/tech/structure cho fee-demo (BigDecimal, Quarkus 3, jqwik). Khi prompt mới ra đúng record *Response, có test — chỉ vào đây.
Kiro IDE

Autopilot & Agent Focus Mode

  • Supervised: duyệt từng diff — hợp khi mới làm quen hoặc code nhạy cảm.
  • Autopilot: tự chạy task lớn; vẫn dừng hỏi khi chạy script / command.
  • Agent Focus Mode (experimental): command center quản lý nhiều agent trên nhiều repo, sandbox local hoặc cloud; quay về IDE đầy đủ khi cần sửa tay, debug.
  • Thêm: thả ảnh UI / whiteboard để bám theo, đọc lỗi diagnostics, sinh commit message, hiện credit từng prompt.
Tên repo trong hình chỉ là minh hoạ. Nói rõ Focus Mode còn experimental, đừng hứa dùng production.

Feature phức tạp trên codebase lớn

Dòng cuối là ví dụ sát việc của phòng — luồng có Figma và danh sách API sẵn là đầu vào spec-driven thích nhất.

Kịch bản mở đầu của AWS

Chiều thứ Sáu, đồng nghiệp ping một latency spike. Bạn nhớ case tương tự: metric nào, test nào, log ở đâu — chỉ là phải mở 5 tool cùng lúc.

Với Crew: nhắn một câu, Crew tìm lại lần trước đã làm gì, viết lên, gửi cho đồng nghiệp. Bạn tắt máy; tối thấy note "đã resolve".

Kiro Crew

Chạy khi bạn vắng: lịch, heartbeat, webhook

  • Cron: job định kỳ — kirocrew cron add "digest" "…" --cron "0 7 * * 1-5".
  • Heartbeat: theo dõi PR / deployment tới khi đổi trạng thái rồi báo; lưu dạng checkbox trong HEARTBEAT.md.
  • Webhook có xác thực: sự kiện bên ngoài mở việc mới.
  • Task dài: checkpoint, validate, retry, chạy nhiều giờ.
  • Job không cần reasoning chạy script thuần — không tốn model.
Lệnh cron thật: kirocrew cron add "morning-digest" "…" --cron "0 7 * * 1-5" --timezone "Asia/Ho_Chi_Minh"; cron trigger <id> để chạy ngay khi demo. Heartbeat tạo bằng chat: "theo dõi PR #1, đổi trạng thái thì báo tôi".
Kiro Crew

Nhiều agent, điều phối qua ACP

  • Nhiều conversation chạy đồng thời, context tách biệt.
  • Conversation chính giao subagent (research, implement, review), kết quả trả về cha — cha giữ mục tiêu.
  • Activity view: mỗi agent một card, thấy reasoning, từng tool call, kết quả theo thời gian thực.
  • Tool request có thể bắt buộc duyệt.
  • Apps: DevFleets (worktree), Task Runner, Issue Radar, LaunchDarkly; tự xây bằng App SDK.

Không phải hộp đen: thấy từng bước agent nghĩ và làm.

Demo: prompt "chạy song song hai việc: research jqwik + viết test lô lẻ" → mở Activity view. Điểm ăn tiền với người lo "AI tự chạy": thấy hết từng tool call.
Kiro Crew

Bảo mật nhiều lớp & mô hình mở

  • Chạy trên hạ tầng bạn kiểm soát: laptop, VM, container — không cần AWS account, không control plane của AWS.
  • OS sandbox · command deny-by-default · chặn pattern đáng ngờ và sensitive path · validate input.
  • Redact credential · audit log có ký mọi action · dashboard bind local mặc định.
  • Apache 2.0, governance công khai — nhưng harness bên dưới vẫn đóng, cần Kiro account; ngốn token hơn CLI vì subagent chạy song song.
Với công ty chứng khoán: "chạy local, audit log có ký, deny-by-default" là thứ đem nói với bảo mật. Nhưng nói thật: harness đóng, token vẫn đi qua Kiro.
